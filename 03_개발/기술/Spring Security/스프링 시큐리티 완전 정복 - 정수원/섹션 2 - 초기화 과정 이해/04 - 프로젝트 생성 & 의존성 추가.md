# 자동 설정에 의한 기본 보안 작동
## 개념
- 자동 설정 : Spring boot 에서 지원하는 기능으로 우리가 설정을 직접 하는 것이 아니라 자동적으로 어떤 Bean 이 만들어지거나 어떤 Bean 에 관련한 설정들이 이루어지는 것
- 서버가 기동되면 Spring Security의 초기화 작업 및 보안 설정이 이루어진다.
- 별도의 설정이나 코드를 작성하지 않아도 기본적인 웹 보안 기능이 현재 시스템에 연동되어 작동한다.
## 기본적인 웹 보안 기능
1. 기본적으로 모든 요청에 대하여 인증 여부를 검증하고 인증이 승인되어야 자원에 접근이 가능하다.
2. 인증 방식은 form 로그인 방식과 httpBasic 로그인 방식을 제공한다.
3. 인증을 시도할 수 있는 로그인 페이지가 자동적으로 생성되어 렌더링 된다.
4. 인증 승인이 이루어질 수 있도록 1개의 계정이 기본적으로 제공된다.
	- SecurityProperties  설정 클래스에서 하나의 계정을 생성해준다
	- username: user
	- password : 랜덤 문자열

## SpringBootWebSecurityConfiguration
- 자동 설정에 의한 기본 보안 설정 클래스를 생성하는 설정 클래스
``` java
@Bean
@Order(SecurityProperties.BASIC_AUTH_ORDER)
SecurityFilterChain defaultSecurityFilterChain(HttpSecurity http){
	http.authorizeRequests().anyRequest().authenticated();
	http.formLogin();
	http.httpBasic();
	return http.build();
}
```
- 참고로 향후에 자세히 배우기 때문에 코드에 대한 구체적인 내용을 알 필요는 없다. 다만 설정 클래스가 어떤 일을 하는지 정도만 알아도 충분하다.
### 설정 클래스가 자동으로 하는 3가지 설정
- `SecurityFilterChain` 이라는 클래스 타입을 반환하고 있으며  `defaultSecurityFilterChain`메소드 안에서 `HttpSecurity`타입의 객체를 주입받고 이 객체를 통해 어떤 설정을 하고 있다
- `http.authorizeRequests().anyRequest().authenticated();`
	- `http` 를 통해서 모든 요청에 대해서 어떤 자원에 접근하기 위해서 인증을 받아야 한다고 되어있다
- 인증 방법을 두 가지를 제공하는데 하나가 폼 로그인, 하나가 기본 인증인 HTTP Basic이다. 

## 기본적인 웹 보안 기능 작동에 대한 문제점
- 계정을 추가할 수 있어야 하는데 위 기능으로 추가할 수 있는 방법이 없다.
- 계정에 따라 권한이 달라야 하는데 권한을 다르게 줄 수 있는 방법이 없다.
- 시스템에서 필요로 하는 더 세부적이고 추가적인 보안 기능이 필요할 때 문제점
- 그래서 우리는 직접 커스텀하여 보안 작동을 위한 어플리케이션을 만들고 설정할 것이다.

- 그래서 User 클래스의 `name`과 `password`를 가지고 와서 메모리에 저장하는 초기화 과정이 있다는 것을 알 수 있다.

## 정리
- 이렇게 해서 우리에게 하나의 계정이 제공이 된 것이며, 우리가 브라우저로 접근하여 로그인 하면 인증이 되어 계속 인증을 유지한다. 
- 인증을 유지하기 전에 초기화 과정 속에서 웹 보안 기능이 기본적으로 동작을 하기 때문에 우리는 로그인 페이지로 인증을 해야 했다.
- 이제 우리는 그 초기화 과정을 살펴보도록 한다.

![[Pasted image 20260730053341.png]]
- `DefaultWebSecurityCondition`클래스는 기본 웹 보안 설정을 자동으로 만들어도 되는 상황인지 조건을 검사하는 클래스이다.
	- `DefaultWebSecurityCondition`은 여러 조건을 한데 묶어 검사하기 위해 `AllNestedConditions`를 상속하고 있다. `AllNestedConditions`는 이름 그대로 내부에 선언된 모든 조건이 만족되어야 전체 조건을 만족한 것으로 판단한다.
- 조건은 다음과 같다.
	- SecurityFilterChain과 HttpSecurity 클래스가 클래스 패스에 존재한다. => Spring Security 의존성 설정을 할 경우 존재하게 된다.
	- 사용자가 만든 SecurityFilterChain Bean이 없다.

#### 정리
- 다시 `defaultSecurityFilterChain`메소드가 있는 곳으로 돌아와서 Debug 모드로 구동한다.
- 위 조건들이 참이기 때문에 해당 중단점에 도달하는 것을 볼 수 있다. 만약 위 조건이 참이 아니면 해당 중단점으로 오지 않는다.
![[Pasted image 20260730054511.png]]
- 일단 `defaultSecurityFilterChain`의 메소드를 보면 `HttpSecurity` 객체가 주입 되고 있는 것을 알 수 있다.
- 이 클래스 객체로 간단하게 위와 같은 설정을 하고 있는 것이다.
