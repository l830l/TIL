# 1.1 코딩테스트란?
- 지원자가 알고 있는 자료 구조와 알고리즘 등을 이용하여 문제를 해결해나가는 능력을 평가하는 시험

# 1.2 코딩 테스트를 보는 이유
- 개발자의 능력은 효율적인 설계에서 판가름 난다. 즉, 정확하고 효율적으로 만들어야 한다.

## 1.2.1 문제 해결 과정을 보는 것
- 코딩 테스트에서는 주어진 문제를 이미 알고 있는 알고리즘과 자료 구조를 응용해서 해결해야 한다. 이 과정에서 개발자에게 필요한 문제 해결 과정을 엿볼 수 있다
- 먼저 개발자는 주어진 문제를 정확하게 파악해야 한다. 끊임없이 문제에서 요구하는 방향으로 문제를 해결하고 있는지 생각하며, 이는 개발자의 문제 파악 능력을 확인하는 데 많은 도움이 된다.

## 1.2.2 똑같은 결과를 빠르고 효율적으로
- 문제에서 요구하는 정답을 구할 수 있는 코드라 하더라도 정답을 구하는 과정이 효율적이지 못하면 좋은 코드라고 할 수 없다.
- 코딩 테스트에서 문제를 푸는 시간도 제한되어있지만, 코드의 실행 시간에도 제한이 있다.

# 1.3 코딩과 디버깅
## 1.3.1 잘 짠 코드란?
- 가독성과 효율성으로 읽기 쉬운 코드는 로직에만 집중할 수 있으므로 이해하기 쉽고 실수가 있어도 쉽게 잡아낼 수 있다. 
- 코드가 길어지거나 중복이 발생하면 변수, 메서드, 클래스를 적극 활용하고 역할에 맞게 이름을 붙인다. 

## 1.3.2 코드를 짤 때 흔히 하는 실수들
- 설계에 약하거나 프로그래밍을 접한 지 얼마 되지 않았으면 프로젝트를 자주 엎으면서 설계를 연습한다.

## 1.3.3 디버깅과 시행착오 줄이기
- 코드를 단계 별로 작성한다.
- 하나의 단계를 작성한 후 로그를 찍어 보며 검증한다.
- 단계 검증이 실패하면 검증이 실패한 단계 내에서 더욱 자세히 로그를 찍어본다.
